# Практическая работа №3 — Процессы в Linux

## Цель работы

Изучить процессы Linux и их состояния, научиться работать с `fork()`, `exec()`, `wait()`, исследовать дерево процессов, зомби, сироты и механизм Copy-on-Write.

## 1. Дерево процессов — ptree.py

Файл `ptree.py` получает информацию о процессах непосредственно из `/proc`.

Используются данные:

* PID — идентификатор процесса;
* PPID — идентификатор родительского процесса;
* State — состояние процесса;
* VmRSS — используемый объём оперативной памяти;
* Name — название процесса.

Программа отбирает процессы текущего пользователя и строит дерево с помощью отступов.

### Запуск

```bash
python3 ptree.py
```

### Пример результата

```text
Process tree for current user
==================================================
1234 [S (sleeping)] RSS=12345 kB bash
  1250 [S (sleeping)] RSS=54321 kB python3
```

PID и значения RSS зависят от текущего состояния системы.

## 2. Создание процессов — runner.py

Файл `runner.py` создаёт заданное количество дочерних процессов с помощью `fork()`.

Каждый дочерний процесс запускает переданную команду через `exec()`.

Родительский процесс использует `waitpid()` и получает код завершения каждого дочернего процесса.

Также измеряется время выполнения.

### Запуск

```bash
python3 runner.py 3 echo Hello
```

### Пример результата

```text
Hello
Hello
Hello
PID 2001: return code = 0, time = 0.001 sec
PID 2002: return code = 0, time = 0.001 sec
PID 2003: return code = 0, time = 0.001 sec
```

## 3. Зомби — zombie.py

Файл `zombie.py` создаёт дочерний процесс.

Ребёнок завершается, но родитель некоторое время не вызывает `wait()`.

В этот период завершившийся ребёнок находится в состоянии Zombie.

### Запуск

```bash
python3 zombie.py
```

Для наблюдения использовалась команда:

```bash
ps -o pid,ppid,state,cmd -u $USER
```

Пример:

```text
PID  PPID S CMD
3000 2500 S python3 zombie.py
3001 3000 Z [python3] <defunct>
```

Состояние `Z` означает Zombie.

После вызова `waitpid()` родитель забирает статус завершившегося процесса, поэтому зомби исчезает.

---

## 4. Сирота — orphan.py

Файл `orphan.py` создаёт дочерний процесс, после чего родитель сразу завершается.

Дочерний процесс продолжает работать самостоятельно.

После завершения родителя ребёнок получает нового родителя — процесс, который выполняет функцию усыновления сирот в данной системе.

### Запуск

```bash
python3 orphan.py
```

Для проверки использовалась команда:

```bash
ps -o pid,ppid,state,cmd -u $USER
```

PPID ребёнка изменяется после завершения первоначального родителя.

В WSL конкретный процесс-усыновитель зависит от конфигурации среды и может быть `systemd`, `systemd --user` или другим subreaper.

## 5. Copy-on-Write — cow.py

Файл `cow.py` создаёт большой список и затем выполняет `fork()`.

После `fork()` родитель и ребёнок используют страницы памяти совместно до тех пор, пока одна из сторон не изменяет данные.

Ребёнок изменяет большой список, после чего Linux создаёт отдельные копии изменяемых страниц.

### Запуск

```bash
python3 cow.py
```

Измеряется RSS ребёнка до и после изменения большого списка.

Пример:

```text
Parent RSS before fork: ...
Child RSS before modification: ...
Child RSS after modification: ...
Parent RSS after child modification: ...
```

После изменения списка RSS ребёнка увеличивается, что демонстрирует механизм Copy-on-Write.

## 6. Проверка процессов после выполнения

После завершения практической работы была выполнена проверка:

```bash
ps -o pid,ppid,state,cmd -u $USER
```

Также можно использовать:

```bash

```

Скрипты не должны оставлять работающие фоновые процессы или зомби после завершения.

## 7. Ответы на контрольные вопросы

### 1. Почему fork возвращает два разных значения?

`fork()` создаёт новый процесс.

В дочернем процессе `fork()` возвращает `0`.

В родительском процессе `fork()` возвращает PID созданного ребёнка.

Это позволяет программе определить, в какой ветке она находится:

```text
fork()
  |
  +-- parent → PID ребёнка
  |
  +-- child  → 0
```

### 2. Что изменится, если вызвать exec без предварительного fork?

`exec()` не создаёт новый процесс.

Он заменяет текущую программу другим процессом.

Поэтому если вызвать `exec()` без `fork()`, текущий процесс перестанет выполнять исходную программу и начнёт выполнять указанную команду.

Если необходимо сохранить родительский процесс и отдельно запустить другую программу, обычно сначала используется `fork()`, а затем в дочернем процессе — `exec()`.
